# Atribuição por allowlist — recorte laboratorial F42

`ATTRIBUTION_ALLOWLIST` é JSON privado de configuração indexado por ID de projeto, ID de página (`legacy` no gateway legado), depois pela URL exata aprovada, depois pelo nome UTM e seus valores públicos permitidos. Exemplo sintético: `{"projeto":{"pagina-id":{"https://site.example/checkout?plan=basic":{"utm_campaign":["spring"]}}}}`. A URL deve passar pela validação existente de destino; o padrão é não copiar nada. Somente utm_source, utm_medium, utm_campaign, utm_content e utm_term são aceitos, com valores explícitos e limitados. Alterações exigem reinício do gateway.

A configuração e os valores permitidos são enviados ao navegador para destinos das decisões elegíveis: são públicos. Nunca cadastrar dados pessoais, tokens, click IDs ou segredos. A sintaxe não detecta automaticamente todos os dados sensíveis; cabe ao administrador fornecer apenas rótulos públicos. O valor da URL de entrada só é copiado se for exatamente um dos rótulos públicos configurados, ocorrer uma única vez e não houver nome equivalente no destino aprovado; parâmetros existentes prevalecem. Não há consulta no clique. Configuração inválida desativa propagação, sem alterar o destino aprovado. Stealth, alocação, validade de decisão e aprovação continuam precedendo a propagação.

Provas focadas: `tests/attribution.test.ts`, `tests/f21.test.ts` e `tests/gs06.test.ts`. São recortes locais: GS18 integral, configuração no painel, revisão de segurança final e validação integrada permanecem pendentes. Não registrar valores brutos como fatos ou atribuir vendas a eles.

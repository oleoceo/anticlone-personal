# Gateway HTTPS de observacao

Estado: IMPLEMENTADO PARCIALMENTE. Perfil Linux para preparacao de PILOT_OBSERVE; nao conclui operacao VPS, GS01/GS11/GS16 integrais ou protecao ativa. Executar publicacao somente depois de autorizacao humana. Sem deploy automatico na CI.

## Fronteira e configuracao

Internet -> Nginx TLS :443 -> Node 127.0.0.1:3000 -> PostgreSQL 127.0.0.1:54332. O proxy permite apenas scripts, canarios, observacoes, decisoes e healthz. Admin nao integra este Compose e nunca e upstream do Nginx. Administracao existente permanece em 127.0.0.1:3001, via SSH privado; seu HTTP local nao deve ser republicado. Este perfil pressupoe VPS Linux dedicada/confiavel: processos locais e acesso Docker tem autoridade; nao e isolamento contra outro usuario privilegiado da VPS.

Nao colocar CDN, Cloudflare proxy ou outro balanceador na frente deste perfil. O IP usado para limite e o peer TLS direto; headers enviados pelo cliente sao sobrescritos. Nginx fixa Host e proto, remove Forwarded/X-Forwarded-Host/X-Real-IP e substitui X-Forwarded-For por um unico endereco. Node exige peer loopback e essa autoridade exata. IP nao e identidade nem evidencia de hospedagem, nao e persistido nem usado para risco. Nao configurar real_ip_header ou proxy_add_x_forwarded_for sem nova revisao/teste.

O proxy limita 2 requisicoes/s por IP com burst 20, 10 conexoes por IP, corpo de 2048 bytes e timeouts. Node aplica 120 requisicoes/min por IP e 1200/min globais, mapa limitado a 1200 entradas e reinicio da janela em 60 s, sem persistir enderecos. NAT compartilha o orcamento; abuso distribuido ainda pode degradar disponibilidade. 429 e temporario; Node inclui Retry-After. Limites globais legados de 60/min continuam apenas em LAB. Banco usa pool maximo 5, conexao 2 s, statement 3 s e query 4 s; falhas retornam 503 na observacao/saude e OBSERVE_ONLY na decisao. Proxy devolve 502/504 sem inventar sucesso. Scripts indisponiveis preservam navegacao nativa.

## Preparacao offline

1. Escolher hostname operacional separado do painel e origens sob controle do dono. Este perfil continua um projeto por processo. LAB usa banco e configuracao separados; nao reutilizar politicas laboratoriais como aprovacao operacional.
2. Preparar diretorio privado fora do Git, com proprietario root:root e permissao 0700, arquivos de segredo root:root 0600. Nginx inicia como root com capacidades limitadas e nao pode ignorar permissoes Unix; arquivos 0600 de outro usuario nao funcionam. Certificado valido para o hostname em `fullchain.pem` e chave em `privkey.pem`, incluindo cadeia intermediaria; renovacao deve ser operada e monitorada pelo dono. Nao gerar nem publicar credenciais com comandos registrados em logs. Nao usar `local-test-only` do Compose antigo. `DATABASE_PASSWORD_FILE` aponta ao arquivo privado contendo apenas senha de banco; `GATEWAY_ENV_FILE` aponta ao arquivo privado de ambiente. Compose env_file nao e cofre: usuarios com acesso Docker/root podem ler segredos.
3. O arquivo privado do gateway deve conter `DATABASE_URL` para usuario/banco anticlone em 127.0.0.1:54332 (senha percent-encoded), `PROJECT_ID`, `PUBLIC_GATEWAY_HOST`, `PILOT_ORIGINS` (array JSON de origens HTTPS exatas) e `SMTP_PORT=1`. Nao incluir credenciais administrativas ou SMTP. ALERTAS EXTERNOS NAO IMPLEMENTADOS; a porta 1 mantem envio indisponivel, com intencoes/historico existentes e sem falsa declaracao de entrega. Nao incluir ALLOWED_ORIGIN/LAB_CONTROLLED_ORIGIN/LAB_CONTROLLED_RISK.
4. Em checkout aprovado: `npm ci`, `npm run build`. Exportar somente `PUBLIC_GATEWAY_HOST` no terminal e executar `node dist/apps/https-config.js /caminho/privado/nginx.conf`. O renderer recusa hostname invalido e sobrescrita. Executar com sudo preservando explicitamente PUBLIC_GATEWAY_HOST, ou instalar o resultado com sudo install -o root -g root -m 0600 no diretorio privado root; certificado e chave tambem precisam pertencer a root:root. Nao alterar o template por request; nao versionar a configuracao privada.
5. Construir imagem `docker build -f infra/https/Dockerfile -t anticlone-pilot:<SHA> .`. Guardar a imagem anterior por SHA, nao sobrescrever tags. Exportar GATEWAY_IMAGE, GATEWAY_ENV_FILE, DATABASE_PASSWORD_FILE, NGINX_CONFIG e TLS_DIRECTORY (caminhos absolutos). `docker compose -p anticlone-pilot -f infra/https/compose.yaml config --quiet` valida sem imprimir segredos. Nunca anexar saida de `config` sem `--quiet` nem `docker inspect` a tickets.
6. Validar Nginx sem publicar porta: `docker run --rm --network none -v "$NGINX_CONFIG:/etc/nginx/nginx.conf:ro" -v "$TLS_DIRECTORY:/run/tls:ro" --read-only --tmpfs /tmp --tmpfs /var/cache/nginx --cap-drop ALL --cap-add NET_BIND_SERVICE --cap-add SETUID --cap-add SETGID --cap-add CHOWN --security-opt no-new-privileges:true nginx:1.28-alpine nginx -t`. Arquivos de certificado devem ser reais, nao symlinks que escapem do diretorio montado. A imagem Nginx tem tag de release; atualizacoes/digests devem passar pela mesma CI antes do uso.

## Instalacao autorizada e smoke

Somente depois de autorizacao para operacao, portas e credenciais: iniciar apenas postgres com `docker compose -p anticlone-pilot -f infra/https/compose.yaml up -d postgres`. O volume novo executa SQL 001-024 em ordem uma unica vez. Nao apontar a banco legado, nao executar novamente SQL 016/021 em volume existente. Falha de inicializacao exige investigar o primeiro erro e preservar volume; nao executar down -v. Este PR nao implementa migrador de upgrade ou restore.

Cadastrar o projeto via API administrativa local autenticada (contrato existente em `docs/ADMIN-AUTH-LAB.md`), ou provisionamento parametrizado sob controle do dono, antes de iniciar gateway. PROJECT_ID e origem persistida precisam corresponder a PILOT_ORIGINS. A interface administrativa atual continua laboratorial; nao publicar seu login. O gateway recusa projeto inexistente ou configuracao LAB no modo piloto.

Depois iniciar gateway e proxy com o mesmo Compose; verificar portas com `ss -ltn` (somente 443 deve ser publica; 3000, 3001 e 54332 em loopback). Executar `node dist/apps/installation-smoke.js https://<hostname-operacional>`: valida cadeia TLS padrao do sistema, saude do banco, modo, scripts e bloqueio de rotas administrativas. Nao usar NODE_TLS_REJECT_UNAUTHORIZED=0. Healthz comprova acessibilidade do banco, nao saude completa de fila/SMTP/disco. Se falhar, nao instalar em outras paginas.

Na pagina propria de teste, adicionar `<script async src="https://HOST/runtime.js"></script>`; fallback independente: `<script async src="https://HOST/fallback.js"></script>`. Canarios opcionais: imagem `/canary/html.gif` e background CSS `/canary/css.gif`. Substituir HOST pelo hostname aprovado. CSP precisa permitir scripts e connect-src desse hostname e img-src para canarios; nao enfraquecer CSP globalmente. CSP, bloqueador ou ausencia de sinais nao provam instalacao saudavel. Snippet nao contem segredo; identificadores publicos nao autenticam visitante.

No navegador real: confirmar runtime/core 200, /observe 204, /entry-decision OBSERVE_ONLY, links nativos preservados e nenhuma politica ativa. Repetir em preview autorizado sem incidente; em copia controlada separada confirmar incidente unico nao verificado e timestamp no banco/painel privado. Repetir visita para dedup. Bloquear runtime e testar navegacao nativa. Registrar URL controlada, SHA, navegador, horario e respostas sem dados pessoais. Diagnostico atual: transporte pronto ou falha; instalacao continua NOT_VERIFIED ate observacao em navegador. FULL/PARTIAL/UNSUPPORTED universal e historico de instalacao ainda pendentes (F08/F45).

## Rollback e falhas

Antes da primeira publicacao, ensaiar em ambiente isolado o mesmo smoke, interrupcao do gateway (502 e navegacao nativa), reinicio e rollback para imagem anterior. A CI testa TLS sintetico/Nginx/PostgreSQL/Chromium; nao certifica o certificado/DNS/firewall da VPS. Backup/restore operacional permanece gate separado antes da operacao completa.

Se smoke falhar, parar apenas proxy e gateway com `docker compose -p anticlone-pilot -f infra/https/compose.yaml stop proxy gateway`; manter banco e volume. Para rollback do gateway, restaurar GATEWAY_IMAGE e NGINX_CONFIG anteriores aprovados e recriar gateway/proxy; repetir smoke. Se a versao anterior nao suportar HTTPS_PROXY, manter publicacao parada em vez de remover o bloqueio de encaminhamento. Nunca desativar OBSERVE_ONLY como rollback. Nao reverter esquema nem apagar volume. Para atualizar certificado, validar arquivos, `nginx -t` e reload do proxy; falha exige preservar certificado anterior valido. Logs de acesso estao desativados; logs operacionais rotacionados podem conter dados de rede em erros, acesso privado e retencao local curta. Nao enviar logs brutos sem revisao.

Renderer e smoke sao executados; o smoke confia exclusivamente na CA sintetica local, sem desligar validacao TLS. Isto nao modifica o produto nem prova instalacao publica. O teste unitario da fronteira roda tambem no Windows; o teste Docker e explicitamente ignorado fora desse ambiente. Testes anteriores continuam verificando origens e OBSERVE_ONLY. CI constroi a imagem executavel, sem push ou deploy. Resultado e SHA final constam do PR; nao inferir conclusao por existencia dos arquivos.
